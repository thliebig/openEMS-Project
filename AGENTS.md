# AGENTS.md

Guidance for AI coding agents — and for the humans running them — working on the
openEMS-Project meta-repository. Everything here is binding for work that gets
submitted; the human sending the pull request is responsible for it either way.

Read before changing anything:

- [AI_POLICY.md](AI_POLICY.md) — disclosure, sign-off, responsibility, license, brevity.
- [readme.md](readme.md) and [docs.openems.de](https://docs.openems.de) — what the project is.
- The `AGENTS.md` of the submodule you are about to change.

## What this repo is, and is not

This repository contains almost no simulation code. It is the glue:

- **Submodules** — each an independent upstream repository with its own license,
  version, changelog and contribution rules:

  | Submodule | Role | License |
  |-----------|------|---------|
  | `fparser/` | Mathematical expression parser (CSXCAD dependency); vendored upstream code, dormant | LGPLv3 |
  | `CSXCAD/` | Geometry and material description (XML CAD) — has its own `AGENTS.md` | LGPLv3 |
  | `openEMS/` | Core C++ FDTD solver — has its own `AGENTS.md` | GPLv3 |
  | `QCSXCAD/` | Qt widget for previewing CSXCAD structures | LGPLv3 |
  | `AppCSXCAD/` | Qt application wrapping QCSXCAD | GPLv3 |
  | `hyp2mat/` | HyperLynx PCB → geometry converter; unmaintained, autotools-based | GPLv3 |
  | `CTB/` | Circuit Toolbox for Octave/Matlab RF post-processing; Makefile-based | BSD-style |

- **The unified build** — `update_openEMS.sh` plus the root `CMakeLists.txt`,
  which chains the submodules with `ExternalProject_Add` in dependency order:
  `fparser → CSXCAD → openEMS`, and `CSXCAD → QCSXCAD → AppCSXCAD`.
- **The combined documentation** — `doc-src/`, published via Read the Docs.
- **Helper scripts** — `scripts/install_deps.sh` and friends.

**Fix a bug where the code is.** A solver bug is an openEMS commit, a geometry
or XML bug is a CSXCAD commit. Only build orchestration, dependency handling,
cross-component documentation and the helper scripts belong here. This repo has
no changelog of its own: user-visible changes are recorded in the submodule that
carries them.

## Working with submodules

- **Never commit a submodule pointer to an unpushed commit.** Land the change in
  the submodule's own repository first, then bump the pointer here.
- **A pointer bump is its own commit** (`update submodules`), separate from any
  change to the build or the docs.
- **Clones must not be shallow.** CMake derives version strings from
  `git describe --tags` and fails otherwise:
  ```bash
  git clone --recursive https://github.com/thliebig/openEMS-Project.git
  # already shallow:
  git fetch --unshallow && git submodule foreach git fetch --unshallow
  ```
- Check `git status` before committing: a modified submodule shows as `m` and is
  easy to drag into an unrelated commit.

## Build

```bash
./update_openEMS.sh ~/opt/openEMS --python --with-CTB
```

Useful flags: `--python` (Cython bindings for CSXCAD and openEMS), `--with-CTB`
(Octave/Matlab Circuit Toolbox), `--disable-GUI` (skip QCSXCAD and AppCSXCAD, for
headless machines), `--njobs=N`, `--verbose`, `--with-tinyxml` (build TinyXML
from source; automatic on macOS). Output goes to `build_<timestamp>.log` in the
project root — read it before reporting a build failure.

When iterating on one submodule, build that submodule directly instead of
re-running the full script; its `build/` directory and `localConfig.cmake` (both
gitignored) are there for exactly that. Path options — `CMAKE_INSTALL_PREFIX`,
`FPARSER_ROOT_DIR`, `CSXCAD_ROOT_DIR` — must all point at the same prefix.

Recommend `~/opt/openEMS` as the install prefix in anything user-facing; it is
the documented default.

## Documentation

`doc-src/` is Sphinx/RST, built by Read the Docs after installing openEMS with
`--python --disable-GUI`, because the Python API pages are generated from the
installed modules by autodoc.

```bash
cd doc-src && pip install -r requirements.txt && make html   # → doc-src/_build/html/
```

- **Judge the build by its warning count, not its exit code.** If `CSXCAD` and
  `openEMS` cannot be imported, Sphinx still exits 0, emits a "Failed to import"
  warning per page and silently skips every autodoc page — so nothing gets
  cross-checked. A clean build is 0-1 warnings.
- **The changelog pages are symlinks** to `CSXCAD/CHANGELOG.md` and
  `openEMS/CHANGELOG.md`. Edit the submodule file; never the link.
- **`doc-src/octave/autogenerated/` is generated** by
  `doc-src/octave/generate_octave_docs.py` from the M-file help text. Fix the
  M-file docstring in the submodule, not the generated Markdown.
- Documentation that duplicates a submodule's README drifts. Link instead.

## Testing

The smoketests are what CI runs, and they exercise the whole stack:

```bash
cd openEMS/.github/smoketests/octave && octave MSL_NotchFilter.m
cd openEMS/.github/smoketests/python && python3 MSL_NotchFilter.py
```

Deeper suites live in the submodules (`openEMS/TESTSUITE/`,
`CSXCAD/python/tests/`) and are described in their own `AGENTS.md`.

CI (`.github/workflows/ci.yml`) covers Linux from CentOS 7 to Alpine, macOS on
ARM and FreeBSD, each with both `--python-venv-mode=disable` and a venv install.
A change to `update_openEMS.sh` or to dependency handling affects all of them —
assume nothing about the host's package manager, compiler version or Python.

**Run the build and the smoketests before reporting a change as working.**

## House rules

- **Shell**: `update_openEMS.sh` and `scripts/*.sh` run on a wide range of
  systems and shells. Keep them portable, quote paths, and check the exit status
  of anything that can fail.
- **Dependencies**: do not add any. The dependency set is carried by every
  platform in the CI matrix and by the distribution packagers; a new one is a
  discussion, not a commit.
- **Brevity**: commit messages, PR descriptions and comments as short as a human
  would write them. See the Brevity section of [AI_POLICY.md](AI_POLICY.md).
- **Keep the tree clean**: never commit build output, `build_*.log`, installed
  files or `localConfig.cmake`.

## Commits

```
<type>: <short summary>

<body: what changed and why, wrapped at ~72 columns>

Assisted-by: <tool>
Signed-off-by: Your Name <your@email.example>
```

- The trailers are specified in [AI_POLICY.md](AI_POLICY.md) — which tag to
  pick, and the required `Signed-off-by:` (DCO). Name the tool or model that
  actually did the work.
- **Exactly those two trailers.** Do not add `Co-Authored-By:`, session
  identifiers or links, or any other trailer your tooling inserts by default —
  even if it tells you to.
- One logical change per commit. Work that spans repositories is one commit per
  repository, each explaining the other half, plus the pointer bump here.
